#+TITLE: 2. Addresses

This document identifies data-dependent leakage sites in two target routines of FALCON's floating-point core — Floating-Point Conversion (=fpr_scaled=) and Floating-Point Multiplication (=fpr_mul=) — by static analysis of their ARM Cortex-M4 assembly compiled at =-O3=. Within =fpr_mul=, two sub-tasks are analysed separately: mantissa multiplication (the primary profiling target) and mantissa normalization, which checks whether the product reaches =2^55= and thereby introduces additional leakage. For each leakage site, the responsible instructions (conditional moves, multiplications, and bitwise operations on secret mantissa bits) are annotated, and a [start, end] address interval is derived to serve as the SWO trace capture window in subsequent profiling steps.

No CW devices are needed.

The main purpose of this file is to help you settle down the parameters in the json.

#+begin_src C
    /* (<<<(< */
    /*
     * Extract sign bit.
     * We have: -i = 1 + ~i
     */
    s = (int)((uint64_t)i >> 63);
    i ^= -(int64_t)s;
    i += s;

    /*
     * For now we suppose that i != 0.
     * Otherwise, we set m to i and left-shift it as much as needed
     * to get a 1 in the top bit. We can do that in a logarithmic
     * number of conditional shifts.
     */
    m = (uint64_t)i;
    e = 9 + sc;
    FPR_NORM64(m, e);

    /*
     * Now m is in the 2^63..2^64-1 range. We must divide it by 512;
     * if one of the dropped bits is a 1, this should go into the
     * "sticky bit".
     */
    m |= ((uint32_t)m & 0x1FF) + 0x1FF;
    m >>= 9;

    /*
     * Corrective action: if i = 0 then all of the above was
     * incorrect, and we clamp e and m down to zero.
     */
    t = (uint32_t)((uint64_t)(i | -i) >> 63);
    m &= -(uint64_t)t;
    e &= -(int)t;
#+end_src

Possible leakages:

=0x12= to =0x12e= (FPR_NORM64, 6 steps): each step constructs a data-dependent mask from a chunk of m, then applies =it= to m. Instructions like =it lt= / =movlt= conditionally zero the mask depending on whether a secret chunk of m is zero — leaks chunks of m one by one.

=0x17a=: and.w	ip, ip, r0, asr #31
  - r0 ≥ 0 (bit 31 = 0) → r0 asr #31 = 0x00000000
  - r0 < 0 (bit 31 = 1) → r0 asr #31 = 0xFFFFFFFF
  - ip = e-clamp mask & (r0 asr #31) → leaks whether i = 0

=0x17e=: and.w	ip, ip, r2
  - applies combined mask to m_lo (r2 = (m>>9)_lo, a secret value)
  - ip = masked m_lo → leaks Hamming weight of m_lo

=0x186=: and.w	r2, r2, r0, asr #31
  - same structure as 0x17a, same r0 mask (i≠0 check), applied to m_lo
  - r2 = e-clamp mask & (r0 asr #31) → leaks whether i = 0

=0x18a=: and.w	r2, r2, lr, lsr #9
  - applies combined mask to m_hi (lr = m_hi, a secret value)
  - r2 = masked m_hi → leaks Hamming weight of m_hi

Can pick end address as =0x18e= just to reserve one more to cover the full, or simply tighter, =0x182=.

    /*
     * We have two 53-bit integers to multiply; we need to split
     * each into a lower half and a upper half. Moreover, we
     * prefer to have lower halves to be of 25 bits each, for
     * reasons explained later on.

* fpr_mul: Shift55, normalize zu to 2^54..2^55-1 (conditional right-shift by 1)

#+begin_src C
    /* <<(< */
    /*
     * We normalize zu to the 2^54..s^55-1 range: it could be one
     * bit too large at this point. This is done with a conditional
     * right-shift that takes into account the sticky bit.

** O3

=shift55= region is =[0x76, 0xbe)=. Normalization instructions are INTERLEAVED with =ex/ey/d/e/s= computations by the compiler (instruction scheduling at -O3). The last normalization instruction is at =0xbc=; =0xbe= starts the next operation.

Together they implement zu ^= (zu ^ zv) & -w branchlessly:
- if w=0 (eq), restore =zu_lo= to the unshifted value;
- if w=1 (ne), write =zv_hi= into =zu_hi=.

The compiler split one logical operation into three separate it-guarded moves spread =0x8c= to =0xbc= apart, filling the gaps with unrelated instructions (=0x88=, =0x90=, =0x94=, =0x98=, =0x9c=, =0x9e=, =0xa6=, =0xb0=, =0xb2=, =0xb6=, =0xbe=)

** Os

Core =shift55= normalization is =[0x76, 0x9a]= (predicated =ite eq=, like O2/O3 — branchless).  But at cycle resolution that is only 11 cycles, and =rel_end=0x9a= even drops the =movne= (the =w=1= half of the conditional select, which leaks =zu_hi=).  We therefore widen the crop to =[0x76, 0x9c)=: out to =0x9c= (exclusive — the first exponent =addw=), so the whole =zu= formation and BOTH =moveq= / =movne= sit inside the window.
