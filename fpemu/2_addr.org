#+TITLE: 2. Addresses

This document identifies data-dependent leakage sites in two target routines of FALCON's floating-point core — Floating-Point Conversion (=fpr_scaled=) and Floating-Point Multiplication (=fpr_mul=) — by static analysis of their ARM Cortex-M4 assembly compiled at =-O3=. Within =fpr_mul=, two sub-tasks are analysed separately: mantissa multiplication (the primary profiling target) and mantissa normalization, which checks whether the product reaches =2^55= and thereby introduces additional leakage. For each leakage site, the responsible instructions (conditional moves, multiplications, and bitwise operations on secret mantissa bits) are annotated, and a [start, end] address interval is derived to serve as the SWO trace capture window in subsequent profiling steps.

No CW devices are needed.

└── fpr_of(t[u])                       sign.c:194 → fpr.h:223

Understandable C in PQClean:

#+begin_src C
    /* (<<<(< */
    /*
     * Extract sign bit.
     * We have: -i = 1 + ~i
     */
    s = (int)((uint64_t)i >> 63);
    i ^= -(int64_t)s;
    i += s;

    /*
     * For now we suppose that i != 0.
     * Otherwise, we set m to i and left-shift it as much as needed
     * to get a 1 in the top bit. We can do that in a logarithmic
     * number of conditional shifts.
     */
    m = (uint64_t)i;
    e = 9 + sc;
    FPR_NORM64(m, e);

    /*
     * Now m is in the 2^63..2^64-1 range. We must divide it by 512;
     * if one of the dropped bits is a 1, this should go into the
     * "sticky bit".
     */
    m |= ((uint32_t)m & 0x1FF) + 0x1FF;
    m >>= 9;

    /*
     * Corrective action: if i = 0 then all of the above was
     * incorrect, and we clamp e and m down to zero.
     */
    t = (uint32_t)((uint64_t)(i | -i) >> 63);
    m &= -(uint64_t)t;
    e &= -(int)t;
#+end_src

*** additional =fpr_ursh= section

=fpr_ursh= is the constant-time 64-bit unsigned right shift used by the C helpers (=fpr_trunc=, =fpr_rint=) to shift by a possibly-secret count without falling back to a non-constant-time libgcc routine:

#+begin_src C
static inline uint64_t
fpr_ursh(uint64_t x, int n)   /* shift count n in 0..63 */
{
	/* <<<(<(( */
	x ^= (x ^ (x >> 32)) & -(uint64_t)(n >> 5);  /* if n >= 32, fold hi 32 bits into lo */
	return x >> (n & 31);                        /* then one 0..31 barrel shift */
}
#+end_src

It belongs to /other phases/ of signing, never the input-conversion phase. =fpr_ursh= (=fpr.h:128=, the constant-time 64-bit unsigned right shift) is reached from three callers, all outside the =fpr_scaled= / =fpr_mul= windows:

#+begin_example
do_sign_dyn
├── Gaussian sampling: Zf(sampler)            sign.c:1357
│   └── BerExp                                sign.c:1293
│       └── fpr_expm_p63                      fpr.c: 1287
│           └── fpr_trunc                     fpr.h:  366
│               └── fpr_ursh                  fpr.h:  380
├── output rounding: fpr_rint (t0/t1)          sign.c:854,872,1061,1079
│   └── fpr_ursh                              fpr.h:  313
└── mantissa alignment: fpr_add   (used throughout, incl. FFT)
    └── fpr_ursh                              fpr.c:  533
#+end_example

At =-O0= nothing is inlined, so every =static inline= helper gets its own out-of-line copy.

One nuance worth noting: =fpr_ursh= /does/ get pulled into the FFT region too - but only indirectly through =fpr_add='s mantissa-alignment step (=fpr.c:533=), not through =fpr_scaled= / =fpr_mul=. Our capture window is strictly the =fpr_scaled= and the =x1*y0= =fpr_mul= body, neither =fpr_ursh= nor =fpr_trunc= appears in it - confirming the disassembly observation that those sections are siblings in =fpr.o=, not part of the windows we are profiling.

Possible leakages:

=0x3a=: clz r4, r1
  - r4 = number of leading zeros of |i|'s high word = the FPR_NORM64 normalization shift
  - this directly encodes the bit-length (magnitude) of the secret coefficient i
  - the single strongest leak in the function

=0x44=, =0x46=, =0x4a=: lsls r1, r4 / lsrs.w r5, r0, r5 / lsls r0, r4
  - the mantissa is shifted by the secret count r4
  - both the shift amount (magnitude of i) and the shifted mantissa operands leak

=0x1c=: and.w r2, r2, r4, asr #31
  - r4 asr #31 is the (i != 0) mask → e is zero-clamped when i == 0; leaks whether i = 0

=0x30=: and.w r0, r0, r4, asr #31  (with the 0x22..0x36 block)
  - selects the low vs high word for normalization depending on whether |i|'s high word is zero
  - leaks whether |i| >= 2^32 (a coarse magnitude bit; clz at 0x3a then refines it)

=0x60= .. =0x72=: ubfx r6, r5, #0, #9 ... ands.w r6, r6, #1  (sticky + 0xC8 round table)
  - operate on the low 9 mantissa bits → leak the low mantissa bits / their Hamming weight

=0x7c=: orrs.w r1, r1, r3, lsl #31
  - reapplies the sign mask r3 → leaks the sign of i

The whole function is the window: =[0x00, 0x80]= (the naked asm has no out-of-line tail at -O3; the trailing =nop/mov= at 0x82 appears only at -O0).


** Os

Totally the same as =O3=, except that =fpr.o= gains an additional =.text.fpr_trunc= section. This is /not/ part of =fpr_scaled=.

=fpr_trunc= is a separate =static inline= helper in =fpr.h= that converts an =fpr= (IEEE-754 binary64) to an =int64_t= by truncation toward zero (the float-to-int floor of the absolute value, with the sign reapplied):

#+begin_src C
static inline int64_t
fpr_trunc(fpr x)
{
	/* <<(<((< */
	uint64_t t, xu;
	int e, cc;

	/* Absolute value: left-shift the mantissa into the 2^62..2^63-1
	 * range, then right-shift it back afterwards. */
	e = (int)(x >> 52) & 0x7FF;
	xu = ((x << 10) | ((uint64_t)1 << 62)) & (((uint64_t)1 << 63) - 1); /* )))>)) */
	cc = 1085 - e;
	xu = fpr_ursh(xu, cc & 63);   /* drop the fractional bits */

	/* If the exponent is too low (cc > 63) the shift was wrong: clamp
	 * to 0. Also covers the input == 0 case. */
	xu &= -(uint64_t)((uint32_t)(cc - 64) >> 31);

	/* Reapply the sign if the source value was negative. */
	t = x >> 63;
	xu = (xu ^ -t) + t;
	return *(int64_t *)&xu;
}
#+end_src

It belongs to /other phases/ of signing, never the input-conversion phase. =fpr_trunc= (=fpr.h:366=, float-to-int truncation toward zero) is reached only through the *Gaussian sampler* (exp approximation):

#+begin_example
do_sign_dyn
└── ffSampling → samp = Zf(sampler)              sign.c:1357
    └── BerExp                                   sign.c:1293
        ├── fpr_trunc(fpr_mul(x, fpr_inv_log2))  sign.c:1304   (reduce x mod log2)
        └── fpr_expm_p63(r, ccs)                 sign.c:1331 → fpr.c:1287
            └── fpr_trunc(...)                   fpr.c:1324,1357 → fpr.h:366  (LEAF)
#+end_example

At =-Os= (optimize for size) it keeps a single out-of-line copy (=nm= shows =00000000 t fpr_trunc=), so the extra section shows up when disassembling =fpr.o=; at =-O3= the compiler inlines it into every call site, so no standalone copy exists. It is unrelated to the =fpr_scaled= / =fpr_mul= leakage windows and does not change any address or clip range below.

=shift55= (normalization) region in the asm is =[0x5c, 0x8a]=.

It implements =zu ^= (zu ^ zv) & -w= branchlessly with a mask (no =it=-guarded moves, unlike the C-compiler output): =w = zu >> 55= is formed at =0x64=, the all-ones/zero mask =-w= at =0x68=, the shifted candidate =zv = zu >> 1= is built in (=r7=:=r6=) at =0x6a=..=0x72=, and the XOR-swap =zu ^= (zu ^ zv) & -w= is committed at =0x76=..=0x8a=. ** All clip ranges coincide

The clip ranges are identical at every optimization level, so the leakage in the windows of interest is the same everywhere; it makes no difference which level we analyse for the leakage itself.

The level matters only for the /next/ task (~3_cycloc.org~), where ARM-ETM cycle-location capture *fails for O1, O2, O3, Os but succeeds for O0*, thanks to O0's dead trailing instructions after the return. We therefore build the follow-up tasks (cycle location, template profiling, attack) on O0. The reason is explained below.
